# Стратегия разработки (MVP) для "СистемаКонтроля"

Этот документ описывает измененную стратегию и стек технологий для создания **минимально жизнеспособного продукта (MVP)** в соответствии с новыми требованиями. Основной фокус — быстрая разработка ключевого функционала с использованием стека Node.js + React.

## 1. Предлагаемый стек технологий (MVP)

*   **Бэкенд (REST API):**
    *   **Среда выполнения:** **Node.js**
    *   **Фреймворк:** **Express.js**. Легковесный и популярный фреймворк для создания API.
    *   **Язык:** **TypeScript**. Для повышения надежности и упрощения разработки.
    *   **ORM:** **Prisma**. Современный ORM для работы с базой данных, обеспечивает типобезопасность.
    *   **База данных:** **PostgreSQL**.

*   **Фронтенд (SPA - Single Page Application):**
    *   **Фреймворк:** **React**.
    *   **Сборщик:** **Vite**. Обеспечивает быструю разработку и сборку.
    *   **Язык:** **TypeScript** (TSX).
    *   **UI:** **Bootstrap 5**. Для быстрой разработки адаптивного интерфейса.

*   **Инфраструктура (локальная разработка):**
    *   **Контейнеризация:** **Docker** и **Docker Compose**. Позволит запустить все части приложения (бэкенд, фронтенд, БД) одной командой.

## 2. Стратегия разработки (MVP)

План сфокусирован на достижении минимальных требований для оценки "удовлетворительно".

### Фаза 1: Настройка окружения (1 день)

1.  **Структура проекта:** Создание общей папки для проекта с двумя подпапками: `backend` и `frontend`.
2.  **Настройка Docker:** Создание файла `docker-compose.yml`, который будет настраивать и запускать три сервиса:
    *   `database`: контейнер с PostgreSQL.
    *   `backend`: контейнер с Node.js/Express приложением.
    *   `frontend`: контейнер с React/Vite приложением.
3.  **Инициализация проектов:**
    *   В папке `backend`: настройка Node.js, TypeScript, Express, Prisma.
    *   В папке `frontend`: создание React-приложения с помощью Vite.

### Фаза 2: Разработка базовых модулей (1-2 недели)

1.  **Бэкенд (API):**
    *   **Схема данных:** Определение моделей `User` и `Defect` в `schema.prisma`.
    *   **Аутентификация:** Создание API-эндпоинтов для регистрации и входа (`/register`, `/login`). Пароли будут храниться в хешированном виде.
    *   **CRUD для дефектов:** Создание базовых API-эндпоинтов для управления дефектами (создание, получение списка, обновление, удаление).

2.  **Фронтенд (Клиентское приложение):**
    *   **Создание страниц:** Настройка роутинга для страниц "Вход", "Регистрация" и "Список дефектов".
    *   **Реализация UI:** Создание компонентов для отображения списка дефектов, а также форм для их создания и редактирования.
    *   **Интеграция с API:** Написание логики для отправки запросов на бэкенд для аутентификации и управления дефектами.

### Фаза 3: Минимальное тестирование (1 день)

1.  **Unit-тесты:** Написание 2-3 простых юнит-тестов для проверки одной из функций бэкенда (например, вспомогательной функции для обработки данных).
2.  **Ручная проверка:** Убедиться, что приложение запускается локально и основной функционал (регистрация, вход, создание дефекта) работает.

По завершении этих фаз будет готово локально работающее приложение, реализующее базовый функционал, требуемый для минимальной оценки.
