# План работ по проекту (Оценка 4)

Этот план описывает шаги, необходимые для выполнения технического задания на оценку 4.

## 1. Модернизация `service_users` (Сервис пользователей)

**Цель:** Реализовать аутентификацию и безопасное хранение данных пользователей.

- **Зависимости:** Добавить `jsonwebtoken` для создания JWT, `bcryptjs` для хеширования паролей и `joi` для валидации данных.
- **Регистрация (`POST /api/v1/users/register`):**
    - Внедрить валидацию входных данных (email, password, name).
    - Проверять уникальность email.
    - Хешировать пароль перед сохранением.
    - Изменить путь на `/api/v1/users/register` для версионирования.
- **Аутентификация (`POST /api/v1/users/login`):**
    - Создать новый эндпоинт для входа.
    - Валидировать email и password.
    - Сравнивать предоставленный пароль с хешем в базе.
    - Генерировать и возвращать JWT в случае успеха.
- **Профиль (`GET /api/v1/users/profile`):**
    - Создать эндпоинт для получения профиля текущего пользователя (на основе JWT).

## 2. Модернизация `service_orders` (Сервис заказов)

**Цель:** Реализовать авторизацию и привязать заказы к пользователям.

- **Авторизация:** Все эндпоинты, кроме служебных, должны быть защищены. Логика авторизации будет реализована в шлюзе.
- **Создание заказа (`POST /api/v1/orders`):**
    - Извлекать `userId` из JWT (переданного из шлюза), а не из тела запроса.
- **Получение заказов (`GET /api/v1/orders` и `GET /api/v1/orders/:orderId`):**
    - Реализовать проверку прав: пользователь может видеть только свои заказы.

## 3. Модернизация `api_gateway` (API шлюз)

**Цель:** Централизовать аутентификацию, авторизацию, добавить защиту и трассировку.

- **Зависимости:** Добавить `express-rate-limit` для ограничения частоты запросов и `uuid` для генерации ID запросов.
- **Middleware для JWT:**
    - Создать middleware для проверки JWT на защищённых маршрутах.
    - При успешной проверке извлекать `userId` и передавать его в нижестоящие сервисы через заголовок `X-User-Id`.
- **Маршрутизация:**
    - Обновить все маршруты, добавив префикс `/api/v1`.
    - Защитить все маршруты, кроме `/api/v1/users/register` и `/api/v1/users/login`.
- **Безопасность и трассировка:**
    - Добавить ограничение частоты запросов (rate limiting).
    - Добавить middleware для генерации `X-Request-Id` и пробрасывания его в другие сервисы.

## 4. Конфигурация и окружение

- **Dockerfile и docker-compose.yml:** Убедиться, что новые зависимости корректно устанавливаются при сборке образов.
- **Переменные окружения:** Добавить `JWT_SECRET` для подписи токенов.

## 5. Документация и тестирование

- **API Спецификация:** Создать файл `docs/openapi.yml`, описывающий все реализованные эндпоинты в формате OpenAPI 3.0.
- **Тестирование:** Подготовить Postman коллекцию или набор `curl` команд для демонстрации работы всех функций, включая успешные кейсы и ошибки (например, доступ без токена).
