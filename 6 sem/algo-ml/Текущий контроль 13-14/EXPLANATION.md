# Объяснение к заданиям 13-14

## Что сделано

В `Задание.ipynb` реализованы обе генеративные задачи:

- генерация русских имен по символам;
- генерация текста по символам на основе `The Great Gatsby`.

Также код приведен к локальной структуре проекта:

- имена читаются из `datasets/name_rus.txt`;
- художественный текст читается из `datasets/The-Great-Gatsby.txt`;
- вычисления идут на `device = torch.device("cuda:0")`, если CUDA доступна;
- после крупных этапов вызываются `gc.collect()` и `torch.cuda.empty_cache()`.

## Важный нюанс по данным

Файл `datasets/name_rus.txt` у тебя не в UTF-8, а в `cp1251`. Поэтому в ноутбуке добавлена функция `read_names(...)`, которая сначала пробует `cp1251`, а уже потом другие кодировки. Без этого файл выглядел бы пустым или ломал чтение.

## Базовые термины

- `RNN` (`Recurrent Neural Network`, рекуррентная нейронная сеть) — сеть для обработки последовательностей.
- `GRU` (`Gated Recurrent Unit`) — более устойчивая разновидность рекуррентной сети.
- `token` (`токен`) — элемент последовательности. Здесь токеном является символ.
- `Embedding` (`эмбеддинг`) — таблица, которая переводит индекс токена в плотный вектор.
- `hidden state` (`скрытое состояние`) — внутренняя память рекуррентного слоя.
- `language model` (`языковая модель`) — модель, которая предсказывает следующий токен по предыдущим.
- `<PAD>` — токен выравнивания длины.
- `<UNK>` — токен для неизвестного символа.
- `<SOS>` — начало последовательности.
- `<EOS>` — конец последовательности.
- `temperature` — параметр генерации: чем он выше, тем случайнее выбор следующего токена.

## Раздел 1

### Подготовка датасета

Для русских имен строится символьный словарь (`CharVocab`) со специальными токенами:

- `<PAD>`
- `<UNK>`
- `<SOS>`
- `<EOS>`

Каждое имя превращается в последовательность индексов вида:

- вход `x`: `<SOS> а н н а`
- цель `y`: `а н н а <EOS>`

Это и есть постановка задачи как предсказания следующего токена на каждом шаге.

### Как работает `NameDataset`

`Dataset.__getitem__` возвращает две последовательности:

- `x` — все токены, кроме последнего;
- `y` — все токены, кроме первого.

Тем самым модель на каждом шаге учится отвечать на вопрос: какой символ должен идти дальше.

### Как работает модель

Используется `CharRNNGenerator`:

1. `nn.Embedding` переводит индексы символов в векторы;
2. `nn.GRU` обрабатывает последовательность;
3. `nn.Linear` переводит скрытые состояния в логиты по всем символам словаря.

В `forward` получается тензор логитов размера:

- `[batch_size, seq_len, vocab_size]`

Дальше он разворачивается в двумерный вид для `CrossEntropyLoss`.

### Генерация имени

Функция `sample_name(...)` делает ровно то, что требует задание:

1. стартует с `<SOS>`;
2. прогоняет текущий токен через модель;
3. получает распределение вероятностей;
4. выбирает следующий символ через `torch.multinomial`;
5. повторяет процесс до `<EOS>` или лимита длины.

Во время обучения каждые несколько эпох печатаются сгенерированные примеры.

## Раздел 2

### Подготовка текста

Для `The-Great-Gatsby.txt` текст сначала нормализуется:

- убираются лишние переводы строк;
- выравниваются кавычки;
- сжимаются повторяющиеся пробелы.

После этого строится символьный словарь уже без специальных токенов.

### Как делается датасет

В задании требуется разбить произведение на последовательности длины `seq_len`. Это делает `TextChunkDataset`:

- берется кусок длины `seq_len + 1`;
- первые `seq_len` символов идут во вход `x`;
- следующие `seq_len` символов идут в цель `y`.

Используется небольшой overlap (`перекрытие`) через `step=60` при `seq_len=120`, чтобы модель видела больше контекстов.

### Модель для текста

Архитектура та же по идее, но чуть мощнее:

- `Embedding(64)`
- `GRU(hidden_size=256, num_layers=2)`
- `Linear`

Также включена обрезка градиентов (`gradient clipping`) через `clip_grad_norm_`, чтобы обучение было стабильнее.

### Генерация фрагмента текста

Функция `sample_text(...)`:

1. берет начальную строку `prime`, например `Gatsby `;
2. прогоняет ее через модель, чтобы сформировать скрытое состояние;
3. затем по одному генерирует новые символы;
4. добавляет их к уже построенному тексту.

Это соответствует пункту 2.4.

## Почему выбрана символьная модель

Я сделал обе задачи на уровне символов, потому что:

- для имен это естественная постановка;
- для небольшого учебного ноутбука символьная генерация текста проще и устойчивее, чем word-level модель;
- она требует меньше подготовки словаря и проще стартует на имеющихся локальных данных.

Рекомендуемый порядок:

4. раздел 2.
