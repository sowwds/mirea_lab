# Объяснение решения

Основной файл с решением: `Текущий контроль 5-6/Задание.ipynb`.

Ниже приведено подробное описание того, что сейчас реально находится в ноутбуке, как устроены модели и почему код в некоторых местах сделан именно так. Текст приведен уже с учетом всех последних правок по путям к датасетам, CUDA и освобождению памяти.

## Общая структура ноутбука

В самом начале ноутбука находятся:
- импорты библиотек;
- фиксирование генераторов случайных чисел (`torch.manual_seed`, `np.random.seed`);
- выбор устройства `device` для вычислений;
- общая функция потерь `criterion = nn.CrossEntropyLoss()`;
- настройка базовых путей `BASE_DIR`, `MONKEYS_DIR`, `CATS_DOGS_DIR`;
- вспомогательные функции для обучения, оценки и визуализации.

Это важно, потому что раньше часть ячеек неявно зависела от переменных из других разделов. Сейчас базовые вещи вроде `criterion` вынесены в начало ноутбука, чтобы блоки работали стабильнее.

## Основные термины

- `MLP` (Multi-Layer Perceptron, многослойный перцептрон) — сеть только из полносвязных (`Linear`) слоев.
- `CNN` (Convolutional Neural Network, сверточная нейронная сеть) — сеть, в которой есть сверточные (`Conv2d`) слои.
- `epoch` (эпоха) — один полный проход по обучающей выборке.
- `batch` (батч, пакет) — небольшая группа объектов, которая подается в модель за один шаг.
- `DataLoader` — объект, который выдает данные батчами.
- `accuracy` — доля правильных ответов модели.
- `loss` (функция потерь, ошибка) — число, показывающее, насколько сильно модель ошиблась.
- `CrossEntropyLoss` (кросс-энтропия) — стандартная функция потерь для задачи классификации.
- `feature map` (карта признаков) — выход сверточного фильтра, то есть то, что «увидел» конкретный фильтр на изображении.
- `transfer learning` (перенос обучения) — использование уже предобученной модели и ее дообучение под новую задачу.
- `fine-tuning` (тонкая настройка) — дообучение предобученной модели на новой задаче.

## Вспомогательные функции

В ноутбуке есть набор общих функций, которые используются почти во всех разделах.

### `count_parameters`

Считает количество обучаемых параметров модели.

Зачем это нужно:
- по заданию требуется посчитать число параметров;
- можно быстро понять, насколько модель тяжелая;
- чем больше параметров, тем чаще модель сильнее грузит память и дольше обучается.

### `train_model`

Это основной цикл обучения:
1. модель переводится в режим обучения (`model.train()`);
2. данные идут батчами;
3. считаются предсказания;
4. считается функция потерь;
5. вызывается `backward()` для вычисления градиентов;
6. оптимизатор обновляет веса;
7. после каждой эпохи считается качество на тестовой выборке.

На выходе функция возвращает `history` — словарь с:
- `train_loss`;
- `test_loss`;
- `test_acc`.

### `evaluate_model`

Эта функция:
- отключает обучение (`model.eval()`);
- считает среднюю ошибку на тестовой выборке;
- собирает все правильные ответы и все предсказания;
- считает `accuracy`.

Она нужна, чтобы не дублировать один и тот же код для всех задач.

### `plot_losses`

Строит графики:
- ошибки на обучении;
- ошибки на тесте.

По этим графикам можно понять:
- обучается ли модель вообще;
- не началось ли переобучение (`overfitting`, ситуация, когда модель хорошо запоминает train, но хуже работает на test).

### `show_predictions`

Показывает несколько изображений и подписывает:
- правильный класс (`true`);
- предсказанный класс (`pred`).

Это нужно не только для красоты: по таким картинкам быстро видно, где модель ошибается и какие классы чаще путаются.

### `show_confusion`

Строит матрицу ошибок (`confusion matrix`).

Матрица ошибок показывает:
- строки — истинные классы;
- столбцы — предсказанные классы;
- диагональ — правильные ответы;
- остальные клетки — ошибки.

По ней удобно видеть, какие классы модель путает чаще всего.

### `visualize_first_conv`

Берет выходы первого сверточного слоя и визуализирует их.

Зачем это нужно:
- задание просит показать результат работы первого сверточного слоя;
- можно увидеть, какие простые признаки сеть начинает выделять на первом уровне (границы, пятна, локальные контрасты).

## 1. Fashion MNIST

`FashionMNIST` — это датасет изображений одежды. Изображения:
- черно-белые;
- размером `28x28`;
- 10 классов.

### 1.1 Модель без сверток

Используется `FashionMLP`.

Архитектура:
- `Flatten()` — превращает картинку `28x28` в один длинный вектор длины `784`;
- `Linear(784 -> 256)`;
- `ReLU` (функция активации, которая оставляет положительные значения и обнуляет отрицательные);
- `Dropout(0.2)` (случайно зануляет часть нейронов во время обучения для снижения переобучения);
- `Linear(256 -> 128)`;
- `ReLU`;
- `Linear(128 -> 10)`.

Почему именно так:
- `MLP` не умеет учитывать пространственную структуру изображения;
- поэтому сначала картинка просто разворачивается в вектор;
- несколько полносвязных слоев позволяют модели учить общие зависимости между пикселями;
- `Dropout` добавлен для регуляризации (борьбы с переобучением).

Слабое место такой модели:
- она не понимает, что соседние пиксели на изображении связаны между собой;
- из-за этого она почти всегда уступает сверточной сети.

### 1.2 Модель со свертками

Используется `FashionCNN`.

Архитектура:
- `Conv2d(1 -> 32, kernel_size=3, padding=1)`;
- `ReLU`;
- `MaxPool2d(2)`;
- `Conv2d(32 -> 64, kernel_size=3, padding=1)`;
- `ReLU`;
- `MaxPool2d(2)`;
- затем `Flatten`;
- `Linear(64 * 7 * 7 -> 128)`;
- `ReLU`;
- `Dropout(0.3)`;
- `Linear(128 -> 10)`.

Что это означает:
- первый `Conv2d` учит 32 фильтра (свертки, которые ищут простые локальные шаблоны);
- `MaxPool2d` уменьшает размер карты признаков в 2 раза, то есть делает сеть компактнее и устойчивее;
- второй `Conv2d` ищет уже более сложные комбинации признаков;
- после сверток признаки подаются в полносвязную часть для окончательной классификации.

Почему `CNN` лучше здесь:
- одежда — это изображение, а не просто набор независимых чисел;
- свертки учитывают локальную структуру изображения;
- поэтому такая сеть обычно дает заметно лучшее `accuracy`.

## 2. CIFAR-10

`CIFAR-10` — это цветные изображения размером `32x32`, 10 классов.

В ноутбуке данные нормализуются, то есть значения пикселей приводятся к более удобному масштабу. Это помогает обучению идти стабильнее.

### 2.1 Модель без сверток

Используется `CIFARMLP`.

Архитектура:
- `Flatten()` — переводит картинку `32x32x3` в вектор длины `3072`;
- `Linear(3072 -> 1024)`;
- `ReLU`;
- `Dropout(0.3)`;
- `Linear(1024 -> 256)`;
- `ReLU`;
- `Linear(256 -> 10)`.

Почему модель тяжелее, чем на FashionMNIST:
- изображение цветное;
- размер входа больше;
- значит и входной вектор длиннее.

Минус этой архитектуры тот же:
- она игнорирует структуру изображения;
- поэтому для CIFAR-10 качество у MLP обычно заметно хуже, чем у CNN.

### 2.2 Сверточная модель

Используется `CIFARCNN`.

Архитектура:
- `Conv2d(3 -> 32, 3x3)`;
- `ReLU`;
- `Conv2d(32 -> 64, 3x3)`;
- `ReLU`;
- `MaxPool2d(2)`;
- `Conv2d(64 -> 128, 3x3)`;
- `ReLU`;
- `MaxPool2d(2)`;
- `Flatten`;
- `Linear(128 * 8 * 8 -> 256)`;
- `ReLU`;
- `Dropout(0.3)`;
- `Linear(256 -> 10)`.

- `MaxPool2d(2)`;
- `Conv2d(32 -> 64, kernel_size=3, padding=1)`;
- `ReLU`;
- `MaxPool2d(2)`;
- затем `Flatten`;
- `Linear(64 * 7 * 7 -> 128)`;
Что делает эта модель:
- постепенно извлекает признаки все более высокого уровня;
- сначала это могут быть контуры и текстуры;
- затем более сложные части объектов;
- в конце эти признаки используются для классификации.

## 3. Внешние датасеты через `ImageFolder`

В этом разделе данные читаются не из встроенных датасетов `torchvision`, а из локальных папок.

### Как работает `ImageFolder`

`ImageFolder` ожидает структуру вида:

```text
root/
  class_1/
  class_2/
  ...
```

То есть имена папок считаются именами классов.

### Почему в ноутбуке были правки по путям

У тебя реальные архивы распаковались не идеально “плоско”, а так:

Для обезьян:
```text
data/monkeys/training/training/n0
data/monkeys/training/training/n1
...
data/monkeys/validation/validation/n0
...
```

Если бездумно подать `data/monkeys` в `ImageFolder`, то модель начнет считать классами:
- `training`
- `validation`

Это неверно.

Поэтому в ноутбук была добавлена функция `_resolve_class_root`, которая:
- спускается через технические “обертки” вроде `training/training`;
- ищет реальный корень, где уже лежат папки классов;
- возвращает правильный путь для `ImageFolder`.

### `prepare_imagefolder_loaders`

Эта функция:
- ищет train-папку (`train` или `training`);
- ищет test/validation-папку (`test`, `validation`, `valid`, `val`);
- если обе найдены, использует их напрямую;
- если нет, делает `random_split` (случайное разбиение) из одного общего датасета.

Это сделано потому, что структура у `monkeys` и `cats_dogs` у тебя разная:
- у `monkeys` есть train и validation;
- у `cats_dogs` сейчас есть только `train`, поэтому нужен запасной вариант через разбиение.

### 3.1 Классификация обезьян

Используется `MonkeyCNN`.

Архитектура:
- `Conv2d(3 -> 32)`;
- `ReLU`;
- `MaxPool2d(2)`;
- `Conv2d(32 -> 64)`;
- `ReLU`;
- `MaxPool2d(2)`;
- `Conv2d(64 -> 128)`;
- `ReLU`;
- `AdaptiveAvgPool2d((1, 1))`;
- `Flatten`;
- `Linear(128 -> 64)`;
- `ReLU`;
- `Dropout(0.3)`;
- `Linear(64 -> n_classes)`.

Что здесь важно:
- `AdaptiveAvgPool2d((1, 1))` делает так, что на выходе каждой карты признаков остается одно число;
- это удобно, потому что не нужно вручную угадывать размер после сверток;
- модель получается компактнее и меньше зависит от точного размера изображений.

### 3.2 Классификация кошек и собак

Используется `CatsDogsCNN`.

Архитектура почти такая же, как у `MonkeyCNN`.

Причина проста:
- задача схожа по типу;
- входные данные тоже изображения;
- такая CNN уже достаточно разумна как базовый вариант.

## 4. Transfer Learning

Здесь используются предобученные модели (`pretrained models`) из `torchvision.models`.

Предобученная модель — это модель, которая уже была обучена на большом датасете `ImageNet`.

Почему это полезно:
- первые слои таких моделей уже умеют выделять хорошие общие визуальные признаки;
- не нужно учить сеть “с нуля”;
- на малых датасетах это обычно работает лучше.

В этом разделе используется другая предобработка:
- `Resize((224, 224))`;
- `Normalize(mean=(0.485, 0.456, 0.406), std=(0.229, 0.224, 0.225))`.

Это не случайные числа: это стандартная нормализация под `ImageNet`, на которой обучались `VGG16` и `ResNet18`.

### `prepare_transfer_loaders`

Функция работает аналогично `prepare_imagefolder_loaders`, но использует именно `transfer_transform`, то есть преобразования под предобученные модели.

### 4.1 Обезьяны + `VGG16`

Используются два режима.

#### Полный fine-tuning

Берется `VGG16`, и ее последний слой заменяется на новый `Linear`, у которого число выходов равно числу классов обезьян.

Дальше обучаются все веса модели.

Плюсы:
- модель может лучше адаптироваться к новой задаче.

Минусы:
- это очень тяжелый режим;
- он сильно грузит GPU-память;
- на видеокартах с `4 GB` VRAM легко получить `OutOfMemoryError`.

#### Дообучение только `classifier`

Во втором режиме:
- все параметры модели замораживаются (`requires_grad = False`);
- размораживается только блок `classifier`;
- меняется последний слой.

Это легче по памяти и быстрее по времени.

### Почему в `4.1` была проблема с памятью

У тебя в одной и той же ячейке последовательно обучались:
- `vgg16_full`;
- затем `vgg16_head`.

После первого запуска память не освобождалась полностью, и при создании второй модели происходил `CUDA out of memory`.

Поэтому в ноутбук были добавлены:
- `del vgg16_full`;
- `del optimizer`;
- `gc.collect()`;
- `torch.cuda.empty_cache()`.

То есть между двумя режимами теперь идет явная очистка памяти.

### 4.2 Кошки/собаки + `ResNet18`

Здесь вместо `VGG16` используется `ResNet18`.

`ResNet` (Residual Network, остаточная сеть) отличается тем, что в ней есть остаточные связи (`skip connections`), которые помогают обучать более глубокие сети стабильнее.

Почему здесь выбрана `ResNet18`:
- она легче, чем `VGG16`;
- обычно лучше ведет себя по памяти;
- для задачи кошек и собак это разумный выбор.

В `ResNet18` заменяется последний слой `fc` на новый слой под нужное число классов.

## Что важно знать про запуск

### 1. Не все разделы независимы на уровне данных

Хотя базовые переменные вынесены в начало ноутбука, разделы `3.x` и `4.x` требуют, чтобы:
- каталоги с изображениями реально существовали;
- структура папок была корректно распознана.

### 2. `device = torch.device("cuda:0")`

Сейчас в ноутбуке устройство жестко выставлено как `cuda:0`.

Это нормально, если:
- `torch` видит CUDA;
- нужная GPU уже выбрана через переменную окружения `CUDA_VISIBLE_DEVICES`.

Если CUDA недоступна, такую строку придется заменить на более универсальный вариант через проверку `torch.cuda.is_available()`.

### 3. Для `VGG16` нужно аккуратно подбирать `batch_size`

На видеокартах с маленькой памятью:
- `batch_size=32` почти наверняка слишком большой;
- `batch_size=4` может быть на грани;
- `batch_size=2` — более реалистичный вариант для `VGG16`.
