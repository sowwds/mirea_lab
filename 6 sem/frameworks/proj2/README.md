# proj2

Модульное приложение на `C#` и `.NET 8`, которое загружает расширения из каталога `modules`, учитывает зависимости между ними и инициализирует их через контейнер внедрения зависимостей.

## Что реализовано

- контракт модуля: имя, зависимости, регистрация служб и инициализация;
- загрузка модулей из конфигурации и каталога `modules/net8.0`;
- построение корректного порядка запуска с учетом зависимостей;
- понятные ошибки для отсутствующего модуля и циклических зависимостей;
- регистрация служб модулей через `DI` контейнер;
- демонстрация реального изменения поведения программы модулями.

## Установка

Если `dotnet` еще не установлен, для `Arch Linux`:

```bash
sudo pacman -S dotnet-sdk-8.0 aspnet-runtime-8.0
```

## Структура

- `Core/` — ядро загрузки, сортировки зависимостей и ошибок;
- `src/ModuleContract/` — общий контракт модулей и интерфейсы, доступные ядру и расширениям;
- `src/Modules/` — отдельные модульные библиотеки;
- `modules/net8.0/` — собранные DLL модулей, откуда их загружает приложение;
- `tests/Proj2.Tests/` — автоматические проверки.

## Модули

- `CatalogModule` регистрирует каталог учебных задач.
- `ReportModule` зависит от `CatalogModule`, получает каталог через `DI` и строит текстовый отчет.
- `ExportModule` зависит от `ReportModule`, получает генератор отчета через `DI` и записывает результат в файл.

Дополнительно есть `CycleAlphaModule` и `CycleBetaModule` для проверки сценария циклических зависимостей.

## Сборка и запуск

```bash
cd proj2
dotnet build
dotnet run --no-build
```

После запуска приложение:

- загружает DLL из `modules/net8.0`;
- строит порядок запуска модулей;
- инициализирует их;
- печатает журнал действий в консоль;
- создает файл `output/report.txt`.

## Демонстрационные сценарии

Обычный запуск:

```bash
cd proj2
dotnet run --no-build
```

Ошибка отсутствующего модуля:

```bash
cd proj2
dotnet run --no-build -- --config appsettings.missing.json
```

Ошибка циклических зависимостей:

```bash
cd proj2
dotnet run --no-build -- --config appsettings.cycle.json
```

## Тесты

```bash
dotnet test proj2/tests/Proj2.Tests/Proj2.Tests.csproj
```

Проверки покрывают:

- корректный порядок запуска на нескольких наборах зависимостей;
- ошибку отсутствующего модуля с понятным сообщением;
- ошибку циклических зависимостей с понятным сообщением;
- то, что зависимости реально приходят из `DI` контейнера.

## Почему это каркас, а не набор случайных классов

Ядро знает только контракт `IAppModule`, загрузку сборок и правила разрешения зависимостей. Оно не зависит от конкретных расширений и не требует правок при добавлении нового модуля.

Каждый модуль изолирован в своей библиотеке и меняет поведение приложения только через контракт и контейнер зависимостей. За счет этого новое расширение добавляется отдельным проектом и конфигурацией, а не переписыванием логики запуска.
