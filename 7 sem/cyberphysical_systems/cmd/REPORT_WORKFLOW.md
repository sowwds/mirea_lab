# Конвейер отчётов

Этот файл описывает воспроизводимую сборку отчётов по дисциплине «Программирование киберфизических систем». Источник отчёта — Markdown, а итоговые файлы DOCX и PDF создаёт один скрипт: `cmd/build_report.py`.

## Архитектура

Для каждой практической работы отчёт хранится отдельно от схемы и исходного кода:

```text
pracN/
└── report/
    ├── assets/                 # скриншоты, фотографии и иные вложения
    ├── report_pracN.md         # редактируемый исходник отчёта
    ├── report_pracN.html       # производный файл
    ├── report_pracN.docx       # производный файл
    └── report_pracN.pdf        # производный файл
```

Общие файлы находятся в `cmd/`:

- `build_report.py` — универсальный генератор для любого `pracN/report/report_pracN.md`;
- `report_template.docx` — утверждённый титульный лист;
- `report_rules.pdf` — правила оформления;
- `REPORT_WORKFLOW.md` — эта инструкция;
- `example/` — старые экспериментальные примеры. Они не участвуют в текущей сборке.

Скрипт меняет в копии шаблона только строку `Название практической`. ФИО, группа, дисциплина, преподаватель, эмблема и остальные элементы титульного листа берутся из `cmd/report_template.docx`. Поэтому перед новой сборкой шаблон следует проверять и при необходимости править вручную в OnlyOffice.

## Требования к ПО

Минимальная среда для Linux/Arch:

```bash
paru -S python python-docx chromium poppler
```

Нужны следующие компоненты:

| Компонент | Для чего нужен |
| --- | --- |
| Python 3.10+ | запуск генератора; |
| пакет `python-docx` | создание DOCX и работа с титульным шаблоном; |
| Chromium | печать HTML в PDF; |
| Poppler (`pdftotext`, `pdfinfo`) | определение страниц для оглавления и проверка PDF. |

Проверка установки:

```bash
python3 --version
python3 -c 'import docx; print(docx.__version__)'
chromium --version
pdftotext -v
pdfinfo -v
```

## Формат Markdown

В начале каждого отчёта обязательны заголовок работы и тема:

```markdown
# Практическая работа №1

**Тема:** Архитектура микроконтроллера семейства Cortex-M. Конфигурирование микроконтроллера STM32
```

Поддерживаемые элементы:

- `##` — основные разделы: `Введение`, `1 Теоретические сведения`, `2 Практическая реализация`, `Заключение`, `Список использованных источников`; каждый из них начинается с новой страницы;
- `###` и `####` — подразделы;
- обычные абзацы;
- маркированные (`-`) и нумерованные (`1.`) списки;
- изображения на отдельной строке;
- блоки кода;
- выделение `**жирным**` и фрагменты `` `кода` `` внутри текста.

Генератор намеренно использует небольшой предсказуемый поднабор Markdown. Таблицы, вложенные списки, HTML внутри Markdown и произвольные расширения Markdown не поддерживаются.

### Изображения

Файл помещается в `assets/`, путь задаётся относительно `.md`:

```markdown
![Настройка выводов GPIO в STM32CubeMX](assets/pinout.png)
```

Номер и подпись рисунка создаются автоматически. Внутри нового главного раздела нумерация рисунков начинается заново.

### Листинги и формулы

Любой блок кода, кроме `text` и `plaintext`, получает рамку и номер листинга в пределах главного раздела:

~~~markdown
```c
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
```
~~~

Для формул и расчётов применяется `text` или `plaintext`; он выводится по центру без номера листинга:

~~~markdown
```text
Fcnt = Fclk / (PSC + 1)
```
~~~

Длинные URL в списке источников разрешено оставлять обычным текстом: генератор принудительно переносит их в HTML/PDF, чтобы Chromium не уменьшал масштаб всей страницы.

## Как происходит сборка

Из корня репозитория:

```bash
python3 cmd/build_report.py prac3/report/report_prac3.md
```

Скрипт выполняет следующие действия:

1. читает Markdown и вложения из папки отчёта;
2. создаёт HTML с титульным листом и временный PDF без номеров в оглавлении;
3. через `pdftotext` определяет страницы главных разделов;
4. пересоздаёт HTML и финальный PDF с заполненным оглавлением;
5. создаёт DOCX на основе `cmd/report_template.docx`.

В результате рядом с Markdown перезаписываются только `.html`, `.docx` и `.pdf`. Исходный `.md`, `assets/` и `cmd/report_template.docx` скрипт не изменяет.

PDF сейчас формируется Chromium из HTML, а не экспортируется из DOCX. Поэтому перед сдачей нужно посмотреть **оба** файла: DOCX — в OnlyOffice, PDF — в просмотрщике PDF. Их содержание и нумерация создаются из одного Markdown, но переносы строк могут немного отличаться.

## Проверка результата

После сборки выполните:

```bash
pdfinfo prac3/report/report_prac3.pdf
pdftotext -layout prac3/report/report_prac3.pdf - | less
```

Проверьте:

- формат страницы A4;
- титульный лист, эмблему и отсутствие пустой второй страницы в DOCX;
- оглавление и номера его страниц;
- рисунки, листинги, заключение и список источников;
- перенос длинных URL в PDF;
- соответствие собственного кода и скриншотов фактическим файлам практической работы.

Если изменяется содержание, редактируется только `.md` и при необходимости `assets/`, затем повторяется команда сборки. Если изменяется оформление титульного листа, сначала правится `cmd/report_template.docx`, а затем заново собираются нужные отчёты.
