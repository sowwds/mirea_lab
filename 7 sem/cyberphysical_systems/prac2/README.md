# Практическая работа №2 — GPIO и контроллер светофора

**Тема:** «Принцип работы порта ввода-вывода микроконтроллера GPIO. Выполнение проекта „Светофор“».

Проект моделирует светофор на плате **Nucleo-C031C6**. Логика написана на C с STM32 HAL. Пять светодиодов отображают автомобильный и пешеходный сигналы, а кнопка запрашивает пешеходную фазу.

## Состав папки

- `main.c` — исходный C-код на STM32 HAL;
- `diagram.json` — соединения платы, светодиодов и кнопки в Wokwi;
- `build-local.sh` — локальная сборка `main.c` в ELF/BIN;
- `wokwi.toml` — путь Wokwi к собранной прошивке;
- `.build/` — результат сборки, создаётся скриптом и не является исходником;
- `report/` — Markdown-исходник отчёта, вложения и сформированные HTML/DOCX/PDF;
- `Практическая работа №1. Контроллер светофора(1).docx` — вспомогательный учебный материал.

## Схема и алгоритм

| Устройство | Пин Nucleo-C031C6 | Линия STM32 |
| --- | --- | --- |
| автомобильный красный | D13 | PA5 |
| автомобильный жёлтый | D12 | PA6 |
| автомобильный зелёный | D11 | PA7 |
| пешеходный красный | D9 | PC7 |
| пешеходный зелёный | D8 | PA9 |
| кнопка | D4 | PB10 |

Кнопка соединена с 3,3 В, а `PB10` настроен с `GPIO_PULLDOWN`; нажатие читается как `GPIO_PIN_SET`. В начальном состоянии автомобилям разрешено движение: горит автомобильный зелёный и пешеходный красный.

После нажатия кнопки автомобильный зелёный мигает три секунды, затем на две секунды включается жёлтый. Далее на 10 секунд включаются автомобильный красный и пешеходный зелёный. Пешеходный зелёный мигает ещё три секунды, на две секунды загораются автомобильные красный и жёлтый, после чего схема возвращается в начальное состояние. В этой работе задержки выполняет системная функция `HAL_Delay`.

## Требования

Нужны Arduino CLI, ядро STM32Duino и расширение Wokwi для VS Code:

```bash
paru -S arduino-cli
arduino-cli core update-index
arduino-cli core install STMicroelectronics:stm32
code --install-extension wokwi.wokwi-vscode
```

Расширение Wokwi требует лицензию и, в обычном режиме, доступ к интернету. В VS Code запросить её можно через `F1` → `Wokwi: Request a new License`.

## Локальная сборка и запуск

Откройте именно эту папку в VS Code или перейдите в неё в терминале:

```bash
cd prac2
./build-local.sh
code .
```

`build-local.sh` копирует `main.c` во временную папку `/tmp`, добавляет служебный пустой `.ino` только потому, что он требуется Arduino CLI, и собирает прошивку в `.build/`. В репозитории исходником остаётся только `main.c`.

После успешной сборки откройте `diagram.json`, затем нажмите кнопку запуска в окне схемы или выполните `F1` → `Wokwi: Start Simulator`. Конфигурация `wokwi.toml` загрузит `.build/prac1.ino.bin` и `.build/prac1.ino.elf`.

После изменения `main.c` обязательно снова выполните `./build-local.sh` до запуска симулятора.

## Проверка

1. Запустите симулятор: должны гореть автомобильный зелёный и пешеходный красный.
2. Нажмите кнопку.
3. Убедитесь в последовательности: мигание зелёного автомобиля → жёлтый → автомобильный красный и пешеходный зелёный → мигание пешеходного зелёного → красный и жёлтый автомобиля → исходное состояние.

В проекте нет потенциометров, дисплея и сторонних библиотек. Для проверки отчёта используется отдельная инструкция [REPORT_WORKFLOW.md](../cmd/REPORT_WORKFLOW.md).
