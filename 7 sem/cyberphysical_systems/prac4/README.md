# Практическая работа №4 — ШИМ и регулирование яркости

**Тема:** «Принцип работы таймера в режиме ШИМ. Регулирование яркости светодиода».

Потенциометр напрямую управляет яркостью одного светодиода через аппаратный ШИМ. При неподвижной ручке яркость постоянная, автоматической пульсации нет.

## Схема

| Элемент | Подключение |
| --- | --- |
| Анод LED | D11 / PA7 / TIM3_CH2, AF1 |
| Катод LED | через резистор 220 Ом к GND |
| Потенциометр SIG | A0 / PA0 / ADC_IN0 |
| Потенциометр VCC, GND | 3,3 В, GND |

## Как работает программа

ADC1 измеряет положение ручки с разрешением 12 бит: `0..4095`. Результат напрямую преобразуется в значение сравнения: `CCR2 = 1000 * value / 4095`. Минимум соответствует заполнению 0% (LED выключен), середина — примерно 50%, максимум — 100% (полная яркость).

ШИМ формируется аппаратным TIM3, каналом 2: `PSC = 47`, `ARR = 999`, частота 1 кГц при тактовой частоте 48 МГц. Заполнение меняется через регистр сравнения `CCR2` от 0 до 1000. Частота ШИМ остаётся постоянной. `HAL_Delay(10)` задаёт паузу между измерениями потенциометра; таймер выдаёт импульсы независимо от этого ожидания.

В Wokwi задано `gamma: "1.0"`, чтобы изменение заполнения было нагляднее.

## Разбор основного кода

### Запуск перед циклом

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_ADC1_Init();
MX_TIM3_Init();
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_2);
```

`HAL_Init()` подготавливает HAL и системную временную базу для задержек. `SystemClock_Config()` выбирает внутренний HSI 48 МГц без деления шин. От этой частоты дальше рассчитывается частота TIM3.

`MX_GPIO_Init()` подключает ножки к нужным периферийным модулям, `MX_ADC1_Init()` настраивает измерение потенциометра, `MX_TIM3_Init()` задаёт параметры ШИМ. После настройки `HAL_TIM_PWM_Start()` запускает второй канал TIM3: счётчик начинает работать и выдавать сигнал на PA7. До этого вызова настройки таймера уже записаны, но генерация на выходе ещё не запущена.

`htim3` и `hadc1` — структуры HAL, содержащие выбранный периферийный модуль, его настройки и состояние. Например, `&htim3` передаёт функции адрес структуры для работы с TIM3.

### Цикл `while (1)`: потенциометр → яркость

Этот цикл повторяется всё время работы микроконтроллера:

```c
while (1) {
  HAL_ADC_Start(&hadc1);
  HAL_ADC_PollForConversion(&hadc1, 100);
  value = (uint16_t)HAL_ADC_GetValue(&hadc1);
  HAL_ADC_Stop(&hadc1);

  __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2,
                        PWM_PERIOD_TICKS * (uint32_t)value / 4095U);
  HAL_Delay(10);
}
```

1. `HAL_ADC_Start(&hadc1)` запускает одно измерение напряжения на PA0, куда подключён выход потенциометра.
2. `HAL_ADC_PollForConversion(&hadc1, 100)` ждёт завершения измерения. Число `100` — предельное время ожидания в миллисекундах, а не обязательная задержка на каждой итерации. Если измерение готово раньше, выполнение продолжается сразу.
3. `HAL_ADC_GetValue()` читает результат АЦП. При выбранном разрешении 12 бит он лежит в диапазоне `0..4095`: около 0 В соответствует 0, около 3,3 В — 4095. Приведение к `uint16_t` сохраняет результат в 16-битную переменную `value`.
4. `HAL_ADC_Stop()` завершает работу текущего измерения. Следующая итерация запускает новое.
5. `__HAL_TIM_SET_COMPARE()` меняет значение сравнения второго канала TIM3, то есть регистр `CCR2`. Именно эта строка связывает положение ручки с яркостью.
6. `HAL_Delay(10)` делает паузу около 10 мс перед следующим измерением. Во время неё TIM3 продолжает самостоятельно выдавать ШИМ с последним установленным заполнением. Эта задержка не задаёт частоту ШИМ и не заставляет LED мигать раз в 10 мс.

Разберём выражение из пятого пункта:

```c
PWM_PERIOD_TICKS * (uint32_t)value / 4095U
```

`PWM_PERIOD_TICKS` равно 1000 — это число отсчётов в одном периоде таймера. Формула переводит диапазон АЦП `0..4095` в диапазон сравнения `0..1000`. Приведение к `uint32_t` явно задаёт 32-битную арифметику для промежуточного произведения, которое достигает 4 095 000. Деление целочисленное, поэтому дробная часть отбрасывается; суффикс `U` обозначает беззнаковую константу.

| Показание АЦП `value` | Значение `CCR2` | Заполнение | Что видно |
| --- | --- | --- | --- |
| 0 | 0 | 0% | LED выключен |
| 1024 | 250 | 25% | небольшая яркость |
| 2048 | 500 | 50% | промежуточная яркость |
| 4095 | 1000 | 100% | максимальная яркость |

При неподвижной ручке результат измерения остаётся примерно одинаковым, поэтому заполнение и яркость сохраняются. Отдельных счётчиков для автоматического нарастания и спада здесь нет.

### `MX_TIM3_Init()`: настройка частоты ШИМ

```c
TIM_OC_InitTypeDef channel = {0};
__HAL_RCC_TIM3_CLK_ENABLE();

htim3.Instance = TIM3;
htim3.Init.Prescaler = 48 - 1;
htim3.Init.CounterMode = TIM_COUNTERMODE_UP;
htim3.Init.Period = PWM_PERIOD_TICKS - 1;
htim3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
htim3.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_DISABLE;
HAL_TIM_PWM_Init(&htim3);
```

`channel = {0}` создаёт структуру настроек канала и обнуляет её поля. `__HAL_RCC_TIM3_CLK_ENABLE()` включает тактирование TIM3: без него модуль не сможет работать. `htim3.Instance = TIM3` указывает HAL, какой именно таймер настраивается.

Поля `htim3.Init` определяют работу счётчика:

| Строка | Что задаёт |
| --- | --- |
| `Prescaler = 48 - 1` | делитель входной частоты: 48 МГц / (47 + 1) = 1 МГц; один отсчёт занимает 1 мкс |
| `CounterMode = TIM_COUNTERMODE_UP` | счёт вверх: 0, 1, 2 и так далее |
| `Period = 1000 - 1` | верхнее значение `ARR = 999`; счётчик проходит 1000 значений от 0 до 999 и начинает заново |
| `ClockDivision = TIM_CLOCKDIVISION_DIV1` | без деления внутреннего такта для фильтров и других вспомогательных блоков таймера; частоту счётчика здесь задаёт `Prescaler` |
| `AutoReloadPreload = ...DISABLE` | отключает буферизацию регистра периода ARR; в этой программе период после настройки не меняется |

Частота получается из двух делителей:

```text
F_PWM = F_TIM / ((PSC + 1) × (ARR + 1))
      = 48 000 000 / (48 × 1000)ат в 16-битную переменную `value`.
4. `HAL_ADC_Stop()` завершает работу текущег
      = 1000 Гц

T_PWM = 1 / 1000 = 1 мс
```

`HAL_TIM_PWM_Init()` применяет настройки счётчика и подготавливает таймер к работе в режиме ШИМ. Частота 1 кГц остаётся постоянной при любом положении ручки.

### Настройка второго канала: откуда берётся яркость

```c
channel.OCMode = TIM_OCMODE_PWM1;
channel.Pulse = 0;
channel.OCPolarity = TIM_OCPOLARITY_HIGH;
channel.OCFastMode = TIM_OCFAST_DISABLE;
HAL_TIM_PWM_ConfigChannel(&htim3, &channel, TIM_CHANNEL_2);
```

`TIM_OCMODE_PWM1` выбирает режим PWM1. При счёте вверх и выбранной высокой полярности выход включён, пока `CNT < CCR2`, и выключен в остальную часть периода. `CNT` — текущее значение счётчика, а `CCR2` — граница переключения второго канала.

Например, при `CCR2 = 250` счётчик 250 мкс находится ниже этой границы, поэтому LED включён. Оставшиеся 750 мкс он выключен. Период по-прежнему 1 мс, а заполнение равно 25%. Быстрые импульсы воспринимаются как постоянное свечение с уменьшенной яркостью.

`channel.Pulse = 0` задаёт начальное значение сравнения: до первого чтения потенциометра LED выключен. В дальнейшем цикл меняет его через `__HAL_TIM_SET_COMPARE()`.

`TIM_OCPOLARITY_HIGH` означает, что активному состоянию соответствует высокий уровень на PA7. `TIM_OCFAST_DISABLE` отключает специальный режим ускоренного отклика канала на триггер; для этой непрерывной генерации он не нужен. `HAL_TIM_PWM_ConfigChannel()` применяет эти параметры именно к `TIM_CHANNEL_2`.

При `CCR2 = 0` условие `CNT < CCR2` никогда не выполняется — LED выключен. При `CCR2 = 1000` оно выполняется для всех значений `CNT` от 0 до 999 — получается постоянный высокий уровень и полная яркость. Поэтому максимум сравнения равен 1000, хотя `ARR` равен 999.

### Как сигнал таймера попадает на LED

В `MX_GPIO_Init()` PA7 настроен так:

```c
gpio.Pin = LED_Pin;
gpio.Mode = GPIO_MODE_AF_PP;
gpio.Pull = GPIO_NOPULL;
gpio.Speed = GPIO_SPEED_FREQ_LOW;
gpio.Alternate = GPIO_AF1_TIM3;
HAL_GPIO_Init(GPIOA, &gpio);
```

`LED_Pin` — это `GPIO_PIN_7` порта A, выведенный на D11 платы. Режим `GPIO_MODE_AF_PP` передаёт управление ножкой периферийному модулю и включает выход push-pull. `GPIO_AF1_TIM3` выбирает на PA7 функцию второго канала TIM3. Поэтому менять состояние LED через `HAL_GPIO_WritePin()` в основном цикле не требуется: уровни на ножке формирует таймер.

`GPIO_NOPULL` отключает внутренние подтягивающие резисторы. `GPIO_SPEED_FREQ_LOW` задаёт скорость фронтов выходного драйвера, а не частоту ШИМ.

Для потенциометра PA0 включён в `GPIO_MODE_ANALOG`. В `MX_ADC1_Init()` выбраны `ADC_CHANNEL_0`, разрешение `ADC_RESOLUTION_12B` и программный запуск `ADC_SOFTWARE_START`. Это позволяет читать напряжение с A0 командами из `while`.

## Файлы и запуск

- `main.c` — C-код на HAL: ADC1, TIM3 и цикл регулирования;
- `diagram.json` — плата Nucleo-C031C6, LED, резистор и потенциометр;
- `build-local.sh` — локальная сборка через Arduino CLI;
- `wokwi.toml` — загрузка `.build/prac4.ino.bin` и `.elf`;
- `report/assets/` — папка для скриншотов будущего отчёта.

Требования к установке Arduino CLI и расширения Wokwi описаны в [README практики 2](../prac2/README.md).

Из корня репозитория:

```bash
cd prac4
./build-local.sh
code .
```

Откройте `diagram.json` и запустите `Wokwi: Start Simulator`. После правок `main.c` повторите сборку и перезапустите симуляцию.

## Проверка

1. В минимальном положении потенциометра LED выключен.
2. Поверните ручку к максимуму: яркость должна увеличиваться до максимальной.
3. Оставьте ручку посередине: LED должен сохранять промежуточную яркость без пульсации.

Компиляция проверяет совместимость с HAL. Видимое изменение яркости и реакцию на ручку дополнительно проверяйте в симуляторе.
