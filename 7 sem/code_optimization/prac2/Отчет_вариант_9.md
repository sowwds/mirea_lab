## Задача и исходный алгоритм

Программа умножает квадратные целочисленные матрицы A и B одного размера N×N. Для каждого элемента результата вычисляется скалярное произведение строки A и столбца B:

```text
C[i,j] = Σ A[i,k] · B[k,j],  k = 0…N−1.
```

Исходный вычислительный метод сохранён под именем MultiplyMatricesOriginal для непосредственного сравнения; тело метода не менялось.

Исходный порядок циклов — i → j → k. Для каждого из N² элементов результата выполняется N умножений и прибавлений. Всего N³ таких пар операций и N² начальных присваиваний нуля: **T₁(N) = O(N³)**. Память результата — O(N²), дополнительная память сверх результата — O(1).

Матрица B читается по столбцу, хотя элементы строк расположены последовательно в памяти. Кроме того, алгоритм выполняет умножения даже для нулевых элементов A.

## Новый алгоритм и обоснование

В MultiplyMatrices порядок циклов изменён на i → k → j. Элемент A[i,k] сохраняется в локальной переменной factor. Если он равен нулю, внутренний цикл пропускается. В остальных случаях выполняется прибавление factor · B[k,j] ко всей строке результата. B и результат обходятся по строкам, что улучшает локальность обращений к памяти.

Массив результата при создании уже заполнен нулями. Для каждой ячейки слагаемые по k остаются в прежнем порядке; пропускаются только заведомо нулевые произведения. Поэтому значения результата сохраняются. Арифметика int, включая переполнение в обычном unchecked-режиме проекта, не изменена.

Пусть Z — число ненулевых элементов A. Просмотр коэффициентов требует N² операций, внутренние циклы — Z·N, создание результата — O(N²). Итого **T₂(N, Z) = O(N² + Z·N)**. Дополнительный массив, кроме результата, не создаётся: память результата O(N²), сверх него O(1).

Для плотной A число Z = N², поэтому худшая сложность по-прежнему **O(N³)**. Это оптимизация доступа к памяти, а не уменьшение степени роста для любых данных. Если в каждой строке два ненулевых элемента, Z = 2N и **T₂(N) = O(N²)**: выполняется 2N² умножений вместо N³. Улучшение асимптотики относится именно к такому семейству разреженных входов.

## Методика измерений

Linux, AMD Ryzen 7 4800H, .NET SDK 8.0.318, сборка Release. Время измеряется Stopwatch с дробными миллисекундами. Для каждого алгоритма и размера выполняются два прогревочных вызова и пять измерений; в таблице медиана пяти измерений. Генерация входов и проверка ответов в замер не входят; выделение и заполнение результирующей матрицы входят.

В обе версии передаются одни и те же матрицы, созданные с Random(42). Для замеров установлено DOTNET_TieredCompilation=0: отключено переключение уровней JIT-компиляции, чтобы оно не происходило посреди измерений. Использованы пять размеров: 64, 128, 256, 384, 512. Ускорение S = время исходного / время нового. Данные оформлены таблицами согласно методичке; отдельные библиотеки для построения графиков не потребовались.

## Замеры: плотные матрицы

Все элементы A и B — случайные целые числа от 1 до 9, нулей нет.

| N | Исходный, мс | Новый, мс | Ускорение |
| --- | --- | --- | --- |
| 64 | 0.8843 | 0.6200 | 1.43× |
| 128 | 6.9302 | 4.6486 | 1.49× |
| 256 | 62.8105 | 36.8118 | 1.71× |
| 384 | 196.4715 | 124.6662 | 1.58× |
| 512 | 621.5015 | 180.6899 | 3.44× |

При росте N со 128 до 384, то есть втрое, исходное время выросло примерно в 28.3 раза, новое — в 26.8 раза. Это согласуется с кубическим ростом 3³ = 27 для обеих версий. Улучшение обусловлено меньшими расходами доступа к памяти, а не изменением O(N³). Отдельные точки чувствительны к состоянию кешей, частоте CPU и фоновой нагрузке.

## Замеры: разреженная первая матрица

В каждой строке A ровно два ненулевых элемента: на диагонали и в следующем столбце по кругу. Их значения от 1 до 9; B плотная. Расположение ненулевых коэффициентов не используется как специальное условие в алгоритме: он просматривает все N² элементов A.

| N | Исходный, мс | Новый, мс | Ускорение |
| --- | --- | --- | --- |
| 64 | 0.5398 | 0.0237 | 22.78× |
| 128 | 4.2438 | 0.0980 | 43.30× |
| 256 | 35.1341 | 0.3122 | 112.54× |
| 384 | 120.1072 | 0.7844 | 153.12× |
| 512 | 393.2785 | 1.2530 | 313.87× |

При росте N со 128 до 384 исходное время выросло примерно в 28.3 раза, новое — в 8.0 раза. Это близко к кубическому росту 27 и квадратичному росту 9 соответственно. На N = 512 медиана уменьшилась с 393.2785 до 1.2530 мс, ускорение — 313.87 раза. Этот большой коэффициент относится к разреженному входу, а не к произвольным матрицам.
