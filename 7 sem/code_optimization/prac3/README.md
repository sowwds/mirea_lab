## Что делает программа

Есть события: пользователь, тип действия, значение и время. Функция `process_events` выбирает события типа `click` и возвращает:

- `total_selected` — число выбранных событий;
- `unique_users` — число разных пользователей;
- `top5` — до пяти пользователей с наибольшей суммой значений.

`variant_9_baseline.py` — исходник из задания. `variant_9.py` — оптимизированное решение.

## Что исправлено

В исходнике события сортируются пузырьком. Затем для каждого пользователя заново просматриваются все события. Это даёт квадратичные затраты времени.

В решении используется `sorted` по времени, суммы накапливаются в словаре за один проход. Вместо полной сортировки пользователей выполняются только первые пять шагов отбора максимума.

Почему не просто `sorted` для top5: исходная сортировка выбором может переставлять пользователей с равными суммами. Первые пять шагов сохраняют именно её результат.

Сортировка событий по времени сохранена, чтобы числа float складывались в прежнем порядке. Перестановка слагаемых может изменить округление.

Сложность: в худшем случае было **O(N²)**, стало **O(N log N)**; дополнительная память остаётся **O(N)**. Точнее, сортируются только выбранные события.

## 3. Показать маленький понятный пример

```bash
python - <<'PY'
from variant_9 import Event, process_events

events = [
    Event(1, 10, "click", 5.0, 30),
    Event(2, 20, "click", 8.0, 10),
    Event(3, 10, "click", 7.0, 20),
    Event(4, 30, "view", 100.0, 40),
]
print(process_events(events, "click"))
PY
```

Получится:

```text
{'total_selected': 3, 'unique_users': 2, 'top5': [(10, 12.0), (20, 8.0)]}
```

Объяснение: `view` отбрасывается, у пользователя 10 сумма 5 + 7 = 12, у пользователя 20 — 8. Можно изменить тип последнего события на `click` и запустить снова: пользователь 30 окажется первым.

## 5. Показать замеры на пяти размерах

```bash
python benchmark.py
```

Появится таблица «N / до / после / ускорение». Время — медиана пяти запусков. Генерация событий не входит в замер, обе версии обрабатывают одни и те же данные. Ускорение равно `время до / время после`.

После таблицы выполняется профилирование. Построчный профилировщик существенно замедляет исходник, поэтому дождись завершения команды; оно может занять около минуты или больше в зависимости от нагрузки.

Открыть график:

```bash
xdg-open assets/time_comparison.png
```

На графике время исходной версии растёт значительно быстрее.

## 6. Объяснить профилирование

```bash
cat assets/profile_cprofile.txt
cat assets/profile_lines.txt
```

- **cProfile** показывает затраты по функциям. `ncalls` — число вызовов, `tottime` — собственное время, `cumtime` — время вместе с вызванными функциями.
- **line_profiler** показывает затраты по строкам. `Hits` — число выполнений строки, `% Time` — её доля времени. Основные затраты исходника — внутренний цикл пузырьковой сортировки, сравнения времени событий и повторные проходы по пользователям.

Секунды под профилировщиком не сравниваем с обычными замерами: сам профилировщик добавляет накладные расходы.
