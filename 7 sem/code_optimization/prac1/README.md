## 4. Показать изменения

```bash
diff -u "task/Program.cs" Program.cs
```

Код возврата 1 у diff означает, что файлы различаются, это нормально. Исходник использует другие окончания строк, поэтому для просмотра различий удобнее открыть оба файла в редакторе и включить сравнение.

Объяснить основные места:

- `RecordResult` — один метод вместо повторения записи истории и LastResult. У неизвестной операции нет сообщения, поэтому история не пополняется.
- `Add`, `Sum`, `Display`, `AddEntry` — новые понятные имена. Старые методы оставлены короткими обёртками, чтобы не ломать прежние вызовы.
- `RunExample` — расчёт демонстрационного примера. Получает калькулятор параметром.
- `PrintResults` — вывод результатов.
- Конструктор `History` — копирование записей истории. Теперь цикл копирования не занимает Main.

## 5. Показать другую операцию

Открой `Program.cs`. В методе RunExample временно замени:

```csharp
calculator.PerformOperation("add", 10, 20)
```

на:

```csharp
calculator.PerformOperation("multiply", 10, 20)
```

Повтори:

```bash
dotnet run --project RPKApp9.csproj
```

В строке Results второе число станет 200, а в истории появится `Multiplied 10 by 20`. LastResult останется 10: после умножения выполняется Sum.

Можно проверить `divide` с числами 10 и 0: второе число будет Infinity. Неизвестная строка операции даст NaN без новой записи истории. Это исходное поведение double, его специально не исправляли при рефакторинге.

После показа верни исходную строку `calculator.PerformOperation("add", 10, 20)`.

## Как объяснить оценку качества

Прямое добавление истории было в шести местах, стало в одном. Присваивание LastResult было в трёх местах, стало в одном. Main сократился с 24 строк до 8.

Цикломатическая сложность — условная оценка числа независимых путей: M = 1 + число ветвлений. В старом Main были foreach и if, поэтому M = 3; в новом остался if, M = 2. В PerformOperation осталось четыре case, M = 5: алгоритм операций не менялся. Это оценка отдельных методов, а не всей программы.
