## Что делает программа

`repeated_data(n)` создаёт N записей с пятью случайными числами в каждой. Ответ — кортеж `(число записей, сумма всех значений)`.

`variant_9_baseline.py` — исходник из задания. Он хранит все записи в списке, создаёт описания и группы по статусу с копиями словарей. В ответе используются только количество записей и сумма чисел.

`variant_9.py` — решение. Числа обрабатываются потоком: посчитали сумму одной записи и передали её во внешнюю сумму. Словари, описания, группы и списки значений не сохраняются.

## Что исправлено

Было **O(N)** дополнительной памяти, стало **O(1)** в обычной модели вычислений. Время в обеих версиях **O(N)**: случайных чисел по-прежнему нужно получить 5N. Но создание ненужных объектов убрано, поэтому выполнение также ускоряется.

Два вложенных `sum` нужны для сохранения порядка вычислений: сначала пять чисел одной записи, потом суммы записей. Одна плоская сумма могла бы изменить округление float.

`len(range(n))` возвращает количество без создания списка и сохраняет ноль для отрицательного N.

## 3. Проверить конкретный размер вручную

```bash
python - <<'PY'
import random
import variant_9_baseline as before
import variant_9 as after

n = 10
random.seed(42)
a = before.run_task(n)
random.seed(42)
b = after.run_task(n)
print("До:   ", a)
print("После:", b)
print("Равны:", a == b)
PY
```

Должно получиться `Равны: True`. Можно заменить `n = 10` на `0`, `1000` или `20000`. Seed сбрасывается перед каждой версией, чтобы сравнивались одинаковые случайные числа.

## 5. Быстро показать экономию памяти

```bash
python - <<'PY'
from benchmark import measure_memory
import variant_9_baseline as before
import variant_9 as after

n = 20000
for name, function in [("До", before.run_task), ("После", after.run_task)]:
    current, peak, result = measure_memory(function, n)
    print(f"{name}: пик {peak / 1024:.3f} КиБ; после возврата {current / 1024:.3f} КиБ")
    print("Ответ:", result)
PY
```

Это измерение **tracemalloc**. Пик — максимум отслеживаемых выделений Python внутри вызова. «После возврата» — сколько осталось после завершения функции при удерживаемом результате. В исходнике пик большой, но после возврата временные записи освобождаются. В решении пик почти не зависит от N.

Можно поменять `n` и повторить. Это не весь расход оперативной памяти процесса: Python и загруженные библиотеки сюда не входят целиком.

## 6. Полные замеры и построчный профиль

```bash
python benchmark.py
```

Выводится таблица на пяти размерах: пик памяти до и после, остаток после возврата, коэффициент снижения пика и время выполнения. Время измеряется отдельно от tracemalloc, как медиана пяти запусков.

Затем **memory_profiler** строит построчные профили обеих версий. Этот этап медленный, дождись завершения команды. Для быстрого показа экономии достаточно команды из пункта 5; полные результаты профилирования уже лежат в assets.

```bash
xdg-open assets/memory_comparison.png
cat assets/profile_memory_before.txt
cat assets/profile_memory_after.txt
```

На графике исходная память растёт с N, оптимизированная остаётся почти постоянной.

В профиле `Mem usage` — RSS процесса, `Increment` — изменение памяти, приписанное строке, `Occurrences` — число её выполнений. Смотри на создание `rec`, `description`, `values`, добавление в `records` и `groups[key].append(r.copy())`. Они создают или удерживают ненужные объекты. `r.copy()` копирует словарь поверхностно: список values остаётся общим.

RSS включает весь процесс, библиотеки и страницы, удерживаемые аллокатором. Поэтому для численного сравнения используем отдельные замеры tracemalloc, а memory_profiler помогает найти строки, где растёт память. Нулевой прирост RSS у строки не доказывает отсутствие выделений: Python может использовать уже выделенные страницы.
