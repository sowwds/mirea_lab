# Практическая работа № 4 — Calculator и pytest

Работа по дисциплине «Технологии тестирования программных продуктов»: реализация арифметического класса Calculator, независимых юнит-тестов и измерение покрытия кода.

Участники: Никитин Артемий, Ефремов Алексей. Группа: ЭФБО-10-23.

## 1. Требования по методичке

Источник: [Практическая работа 4. Юнит-тестирование на Python. Основы pytest](Практическая_работа_4_Юнит-тесты_pytest.pdf).

### Требования к Calculator

| Требование | Реализация |
| --- | --- |
| `add(a, b)` — сложение | Возвращает `a + b`. |
| `subtract(a, b)` — вычитание | Возвращает `a - b`. |
| `multiply(a, b)` — умножение | Возвращает `a * b`. |
| `divide(a, b)` — деление | Возвращает `a / b`. |
| При делении на ноль вызывается `ValueError` | Проверяются `0`, `0.0` и `-0.0`; текст исключения — «Деление на ноль». |
| Допустимые типы — `int` и `float` | Проверяются целые и дробные числа, а также их сочетания. |

### Обязательные требования к тестам

| Требование методички | Что сделано |
| --- | --- |
| Позитивные сценарии для всех четырёх методов | Есть проверки сложения, вычитания, умножения и деления. |
| Граничные значения: 0, отрицательные и большие числа | Включены отдельные наборы данных, в том числе числа `10**18`. |
| Негативный сценарий деления на ноль через `pytest.raises` | 4 случая в `test_divide_by_zero`. |
| Параметризация `add` или `subtract`: не менее 4 наборов | Для сложения целых чисел — 6 наборов, для вычитания — 5. |
| Проверка деления с float через `pytest.approx` | Есть деление `7.5 / 2.5`, смешанные типы и периодическая дробь `1 / 3`. |
| Для float использовать `pytest.approx` | Применяется во всех проверках дробных результатов и во всех случаях деления. |
| Не менее 10 тестовых случаев | 36 случаев в 8 параметризованных функциях. Каждая строка параметризации считается отдельным случаем. |
| Покрытие строк Calculator не ниже 90%, показать `--cov` | В выполненном запуске — 100%; команда запуска контролирует порог через `--cov-fail-under=90`. |
| Независимость тестов | Каждый случай создаёт собственный Calculator и не использует результаты других тестов. |

Структура тестов — AAA: подготовка объекта и данных (**Arrange**), вызов метода (**Act**), проверка результата или исключения (**Assert**).

### Что требуется сдать

## 2. Что делает каждый файл и каталог

Основная последовательность работы: `test_calculator.py` импортирует класс из `calculator.py` → pytest выполняет проверки → pytest-cov измеряет выполненные строки → создаются данные покрытия и отчёты → результаты и скриншоты включаются в Markdown-отчёт.

### Исходники, зависимости и документация

| Файл / каталог | Назначение |
| --- | --- |
| [calculator.py](calculator.py) | Содержит класс Calculator и методы `add`, `subtract`, `multiply`, `divide`. Это проверяемый код. Сам файл не запрашивает ввод и ничего не печатает: при `python calculator.py` видимого результата не будет. Методы вызываются из тестов или из другого Python-кода. |
| [test_calculator.py](test_calculator.py) | Импортирует Calculator и содержит 8 тестовых функций. Декораторы `pytest.mark.parametrize` задают входные данные и ожидаемые ответы; pytest создаёт из них 36 случаев. `assert` проверяет целые результаты, `pytest.approx` — дробные, `pytest.raises` — исключение при делении на ноль. Запускать нужно через pytest. |
| [requirements.txt](requirements.txt) | Список прямых зависимостей с фиксированными версиями: pytest запускает тесты, pytest-cov добавляет измерение покрытия и параметры `--cov`. При установке подтягиваются их зависимости, в том числе coverage, которая собирает данные о выполненных строках. Сам requirements.txt тесты не запускает. |
| [README.md](README.md) | Инструкция по требованиям задания, устройству файлов, подготовке окружения, запуску тестов и повторению результатов на CachyOS Linux. |
| [Отчёт ПР4](<ПР4 Ефремов Никитин ЭФБО-10-23.md>) | Документ для сдачи: описание работы, команда и результат запуска, скриншоты и ответы на 5 вопросов. Обновляется вручную, если меняются код или результаты. |
| [Методичка PDF](Практическая_работа_4_Юнит-тесты_pytest.pdf) | Исходное задание преподавателя: теория, требования к классу и тестам, минимальное покрытие, формат сдачи и контрольные вопросы. Для выполнения Python-кода не используется. |
| [.gitignore](.gitignore) | Указывает Git не добавлять `.venv/`, `__pycache__/`, `.pytest_cache/` и `.coverage` как новые отслеживаемые файлы. Не удаляет их с диска и не влияет на запуск. Правила применятся, если каталог находится в Git-репозитории. |

### Результаты измерения покрытия

Эти файлы создаются после запуска тестов с соответствующими аргументами `--cov-report`.

| Файл | Назначение |
| --- | --- |
| `.coverage` | Двоичная база данных coverage со сведениями о выполненных строках. Это промежуточный результат измерения, а не текстовый отчёт. Используется инструментом coverage для построения отчётов. Вручную редактировать не нужно. |
| [coverage.json](coverage.json) | Текстовый отчёт в JSON: общие показатели, выполненные и пропущенные строки по файлам. Удобен для программной обработки и проверки численных результатов; не содержит интерактивного интерфейса. |
| [coverage_summary.png](coverage_summary.png) | Снимок сводного HTML-отчёта: число учитываемых и пропущенных строк, процент покрытия. Вставлен в Markdown-отчёт по относительной ссылке. |
| [coverage_calculator.png](coverage_calculator.png) | Снимок страницы с исходным кодом Calculator и отметками выполненных строк. Также вставлен в отчёт. |

Файлы `.coverage`, `coverage.json` и содержимое `htmlcov/` обновляются инструментами при запуске. PNG создаются отдельно браузером или вручную; повторный запуск pytest их не обновляет.

### Содержимое `htmlcov/`

Каталог создаётся coverage при `--cov-report=html:htmlcov`. Весь отчёт можно читать локально в браузере, без веб-сервера.

| Файл | Назначение |
| --- | --- |
| [index.html](htmlcov/index.html) | Начальная страница: сводная таблица покрытия файлов. Открывайте её первой. |
| [calculator_py.html](htmlcov/calculator_py.html) | Исходный код `calculator.py` с отметками покрытия отдельных строк и счётчиками выполненных, пропущенных и исключённых строк. |
| [function_index.html](htmlcov/function_index.html) | Сводка покрытия по функциям и методам; позволяет оценить покрытие отдельных операций. |
| [class_index.html](htmlcov/class_index.html) | Сводка покрытия по классам, включая Calculator. |
| `style_cb_*.css` | Оформление страниц: цвета, шрифты, таблицы и подсветка строк. |
| `coverage_html_cb_*.js` | Интерактивные возможности отчёта: фильтры, сортировка, переключение отображения и горячие клавиши. |
| `favicon_32_cb_*.png` | Иконка вкладки браузера. |
| `keybd_closed_cb_*.png` | Значок справки по клавиатурным сокращениям. |
| `status.json` | Служебные данные для ускорения повторного построения HTML-отчёта. Для анализа результатов используйте `coverage.json` из каталога `pr4`. |
| `.gitignore` | Автоматически созданное правило Git, исключающее содержимое `htmlcov/` из обычного добавления в репозиторий. На чтение и передачу файлов отчёта не влияет. |

Звёздочки в названиях служебных CSS, JS и PNG обозначают автоматически сформированную часть имени, которая может измениться при обновлении coverage. Если передаёте HTML-отчёт, копируйте весь `htmlcov/`, чтобы сохранились оформление и интерактивные функции. Его файлы вручную не правятся: изменения кода и тестов вносятся в исходники, после чего отчёт создаётся повторно.

### Окружение и кеши

| Каталог / файл | Назначение и способ создания |
| --- | --- |
| `.venv/` | Изолированное окружение этой работы. Создаётся командой `uv venv`; зависимости устанавливаются сюда, отдельно от системного Python. |
| `.venv/bin/python` | Интерпретатор выбранного окружения. Через него запускается pytest, чтобы использовались именно установленные для работы пакеты. |
| `.venv/bin/pytest` | Команда pytest из окружения. В инструкции используется равнозначный запуск `.venv/bin/python -m pytest`, который явно указывает Python. |
| `.venv/lib/python3.12/site-packages/` | Установленные pytest, pytest-cov и их зависимости. Управляется установщиком пакетов, вручную править не нужно. |
| `.venv/pyvenv.cfg` | Сведения об окружении: базовый Python, версия и доступ к системным пакетам. Создаётся вместе с `.venv`. |
| `.pytest_cache/` | Кеш pytest между запусками. Например, `v/cache/nodeids` хранит идентификаторы найденных тестовых случаев. Не содержит реализацию тестов и не заменяет отчёт. |
| `.pytest_cache/README.md`, `.gitignore`, `CACHEDIR.TAG` | Автоматически создаваемые пояснение, правило исключения из Git и метка каталога кеша. Их не нужно готовить для сдачи. |
| `__pycache__/calculator.cpython-312.pyc` | Скомпилированный байткод Calculator, создаваемый Python при импорте для ускорения следующих загрузок. |
| `__pycache__/test_calculator.cpython-312-pytest-9.2.0.pyc` | Кеш байткода тестового модуля, подготовленного pytest с обработкой `assert` для подробных сообщений об ошибках. |

Кеши создаются автоматически и не являются исходниками. После их отсутствия инструменты создадут их заново. Имена `.pyc` зависят от версий Python и pytest. Окружение `.venv` тоже можно подготовить заново из `requirements.txt`, но для этого потребуется повторная установка пакетов.

## 3. Окружение на вашей системе

- **CachyOS Linux, x86_64** — система, на которой выполнена работа.
- **uv** — уже установленный менеджер Python-окружений и пакетов, использованный при подготовке работы.
- **Python 3.14.8** — текущее окружение `.venv`, пересозданное на этом компьютере; исходное окружение Python 3.12.13 было перенесено с другой машины и не запускалось.
- Зависимости из `requirements.txt`: **pytest 9.2.0**, **pytest-cov 7.1.0**.
- Доступ к пакетному репозиторию для первоначальной установки зависимостей.
- Браузер для просмотра HTML-покрытия и получения скриншотов.

После установки зависимостей тесты выполняются локально, без доступа к интернет-магазину и другим внешним сервисам. Отдельного запуска приложения, сервера или сборки нет: pytest импортирует Calculator и вызывает его методы.

Виртуальное окружение создаётся на том компьютере, где будут выполняться тесты. При переносе работы достаточно исходников и `requirements.txt`; готовую `.venv` переносить не нужно.

## 5. Повторный запуск

### Быстрая проверка всех тестов

```bash
.venv/bin/python -m pytest test_calculator.py -v
```

Ожидаемый итог для текущего кода: `36 passed`. В подробном выводе каждый набор параметров имеет собственную строку со статусом `PASSED`.

### Запуск с отчётом покрытия для сдачи

```bash
.venv/bin/python -m pytest test_calculator.py -v --cov=calculator --cov-report=term-missing --cov-report=html:htmlcov --cov-report=json:coverage.json --cov-fail-under=90
```

| Аргумент | Назначение |
| --- | --- |
| `test_calculator.py` | Запустить тесты из указанного файла. |
| `-v` | Показать результат каждого случая. |
| `--cov=calculator` | Измерять покрытие модуля Calculator. |
| `--cov-report=term-missing` | Вывести в терминал таблицу покрытия и номера непокрытых строк. |
| `--cov-report=html:htmlcov` | Сохранить HTML-отчёт в `htmlcov/`. |
| `--cov-report=json:coverage.json` | Сохранить JSON-отчёт в `coverage.json`. |
| `--cov-fail-under=90` | Завершить команду с ошибкой, если покрытие ниже 90%, даже если сами тесты прошли. |

Для текущих исходников ожидаются следующие значения; время выполнения может отличаться:

```text
collected 36 items

Name            Stmts   Miss  Cover   Missing
---------------------------------------------
calculator.py      11      0   100%
---------------------------------------------
TOTAL              11      0   100%

Required test coverage of 90% reached. Total coverage: 100.00%
36 passed
```

`Stmts` — учитываемые исполняемые строки, `Miss` — невыполненные, `Cover` — процент покрытия. Пустые строки и docstring в этот счётчик не входят. Здесь измеряется покрытие строк; отдельная метрика покрытия ветвей не включена.

При повторном полном запуске файлы покрытия обновляются. Скриншоты и текст Markdown-отчёта автоматически не меняются.

### Запуск отдельных проверок

Только проверки деления на ноль:

```bash
.venv/bin/python -m pytest test_calculator.py::test_divide_by_zero -v
```

Один конкретный набор параметров:

```bash
.venv/bin/python -m pytest 'test_calculator.py::test_add_integers[positive]' -v
```

Посмотреть список случаев без их выполнения:

```bash
.venv/bin/python -m pytest test_calculator.py --collect-only -q
```

Для итогового покрытия запускайте весь файл: частичный запуск измеряет только строки, выполненные выбранными тестами.

## 6. Как повторить отчёт и скриншоты

1. Выполните полный запуск с покрытием из раздела 5 и убедитесь, что все 36 случаев прошли, а покрытие не ниже 90%.
2. Сделайте скриншот терминала с командой, результатом тестов и таблицей покрытия, если хотите дополнительно показать сам прогон.
3. Откройте `htmlcov/index.html` в браузере. Сделайте скриншот сводной таблицы и сохраните как `coverage_summary.png` в `pr4`.
4. В таблице нажмите `calculator.py`. Сделайте скриншот детализации строк и сохраните как `coverage_calculator.png` в `pr4`.
5. Проверьте, что оба изображения отображаются в Markdown-отчёте: в нём уже используются эти относительные имена файлов.
6. Если изменились окружение, код или результаты, обновите соответствующие сведения в отчёте. Укажите фактические значения своего запуска.

Для получения тех же двух снимков без окна браузера используйте установленный на CachyOS Firefox. Команды выполняются из `pr4`; Firefox должен завершить первый снимок до запуска второго:

```bash
firefox --headless --no-remote --screenshot "$PWD/coverage_summary.png" --window-size 1400,900 "file://$PWD/htmlcov/index.html"
firefox --headless --no-remote --screenshot "$PWD/coverage_calculator.png" --window-size 1400,1100 "file://$PWD/htmlcov/calculator_py.html"
```

Сначала создайте свежий HTML-отчёт командой pytest. Firefox нужен только для этих снимков, на выполнение тестов он не влияет. Если браузер сообщает о занятом профиле, получите скриншоты вручную через уже открытый браузер.

## 7. Частые проблемы

| Сообщение / ситуация | Что проверить |
| --- | --- |
| `No module named pytest` | Установите зависимости через Python из `.venv`; запускайте тесты тем же интерпретатором. |
| `unrecognized arguments: --cov...` | В используемом окружении отсутствует pytest-cov. Повторите установку из `requirements.txt`. |
| `No module named calculator` или файл тестов не найден | Перейдите в `pr4`; убедитесь, что `calculator.py` и `test_calculator.py` находятся рядом. |
| Не удаётся создать `.venv` | Проверьте `uv --version` и сообщение команды `uv venv --python /usr/bin/python3 .venv`. Для первоначального получения Python и пакетов может требоваться доступ к сети. |
| На другом компьютере `.venv` не запускается | Создайте собственное окружение и установите `requirements.txt`; не используйте окружение, скопированное с другой системы. |
| Покрытие ниже 90% | Запустите весь `test_calculator.py`, изучите колонку `Missing` и детализацию HTML. После изменения кода добавьте проверки новых сценариев. |
| В HTML видны старые результаты | Повторите полный запуск с `--cov-report=html:htmlcov`, затем обновите страницу браузера. |
| В отчёте не отображаются изображения | Проверьте, что PNG находятся рядом с Markdown-файлом и переданы вместе с ним. |
