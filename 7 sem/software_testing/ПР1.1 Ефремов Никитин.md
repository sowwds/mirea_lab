## Контрольные вопросы

1. **Какие существуют разновидности рабочей тестовой документации?**  
   Checklist, Acceptance Sheet, Test Survey, Test Cases.

2. **Check List: что описывают и когда используют?**  
   Содержит список основных проверок. Используют для типовой функциональности.

3. **Acceptance Sheet: что описывают и когда используют?**  
   Содержит перечень всех модулей и функций приложения, подлежащих проверке. Используют для небольших, до трёх месяцев, простых по бизнес-логике проектов.

4. **Test Survey: что описывают и когда используют?**  
   Содержит перечень всех модулей и функций, а также конкретные проверки; может содержать ожидаемый результат. Используют для средних или больших проектов с понятной бизнес-логикой.

5. **Test Cases: что описывают и когда используют?**  
   Содержат набор входных значений, предусловий, пошаговое описание и постусловия для каждой проверки; всегда содержат ожидаемый результат. Используют для больших и долгосрочных проектов, проектов со сложной бизнес-логикой и большой командой.

6. **От чего зависит степень детализации каждой функциональной проверки?**  
   От выбранного типа тестовой документации.

7. **Какая глубина тестирования указывается для проверок в Acceptance Sheet?**  
   AT.

8. **Какая глубина тестирования указывается для проверок в Test Survey, Test Cases?**  
   Smoke, MAT, AT.

9. **Какие проверки выполняют при тестировании GUI?**  
   Правописание; расположение и выравнивание; длинные названия; соответствие названий форм и элементов GUI их назначению; унификация стиля, цвета, шрифта и названий; эффект «нажатия»; хинты; сообщения об успешном или неуспешном завершении действия и подтверждении действия; изменение размеров окна и масштаба страницы.

10. **Какие общие функциональные проверки выполняют для всего приложения?**  
    Табуляция; «хлебные крошки»; скроллинг; взаимосвязь компонентов; фокус на кнопке для исполнения действий.

11. **Какие общие функциональные проверки выполняют для web-приложения?**  
    Подготовка к тестированию: очистка кэша и cookies; 404 Error; логотип как ссылка на главную страницу; email-нотификации; проверка работоспособности приложения при отключённом JavaScript.

12. **Перечислите базовые проверки для поля ввода данных.**  
    Обязательность ввода; обработка только пробелов; использование пробелов в тексте; минимальное и максимальное число символов; формат данных; формат числовых данных: негативные, дробные с точкой и запятой; специальные символы; редактирование введённых значений; распределение текста по строкам; уникальные данные; автоматическая постановка курсора в первое поле; ввод тегов и скриптов. GUI: название поля, выравнивание названий, расположение текста, унификация дизайна, расположение вводимого текста.

13. **Перечислите базовые проверки для поля загрузки файлов.**  
    Обязательность выбора файла; корректные и некорректные форматы; корректный формат с отсутствующим или изменённым расширением; ограничения на размер, включая нулевой и большой файл; загрузка исполняемых файлов и переименованного EXE-файла; путь к файлу меньше 259, равен 260 и больше 260 символов; ввод корректного пути с клавиатуры; имитация сбоя загрузки; одновременная загрузка нескольких файлов. GUI: унификация дизайна и выравнивание названий загруженных файлов.

14. **Перечислите базовые проверки для ввода даты.**  
    Ввод даты с помощью календаря; ввод даты вручную: разные форматы, номер месяца больше 12, день больше 31, включая февраль; логика работы поля даты. GUI: унификация дизайна, отображение календаря рядом с полем, выравнивание элементов и ссылок календаря.

15. **Перечислите базовые проверки для поля со списком.**  
    Сортировка по алфавиту или смыслу; хинты для значений за границами списка; выбор пункта по первой букве на клавиатуре; ручной ввод, если он разрешён; выбор мышью и клавиатурой. GUI: правописание, подсветка выбранных значений, унификация дизайна.

16. **Перечислите базовые проверки для радиобаттона.**  
    Включение и выключение; не менее двух радиокнопок; одна радиокнопка включена по умолчанию; нельзя включить больше одной; выбранная радиокнопка не сбрасывается после перехода на другую страницу и возврата; активация по символу и тексту. GUI: унификация дизайна, выравнивание с названием и между радиобаттонами, изменение радиобаттона и курсора при наведении.

17. **Перечислите базовые проверки для чекбокса.**  
    Включение и выключение; наличие чекбокса «выбрать/снять все» при более чем десяти чекбоксах; сохранение выбранного состояния после перехода на другую страницу и возврата; активация по символу и тексту. GUI: унификация дизайна, выравнивание с названием, изменение чекбокса и курсора при наведении.

18. **Перечислите базовые проверки для меню.**  
    Переход при выборе пункта меню; визуальное различие текущей вкладки; текущая вкладка отличается визуально и некликабельна; совпадение названий категорий, если меню дублируется. GUI: подсветка категории и изменение курсора при наведении.

19. **Перечислите базовые проверки для таблиц.**  
    Пагинация: «Вперёд», «Назад», «На первую», «На последнюю»; сортировки, включая сортировку по умолчанию; обновление значений после добавления, изменения и удаления данных; единичное и множественное выделение. GUI: унификация дизайна, название, выравнивание иконок сортировки, названий колонок и значений, длинные названия, отображение данных после сортировки.

20. **Перечислите базовые проверки для ссылок.**  
    Переход на соответствующую страницу; открытие загруженной ссылки в новой вкладке или всплывающем окне; форматы ссылок и префиксов; срабатывание только при клике на ссылку. GUI: унификация стилей, расположение, названия, изменение курсора и ссылки при наведении.

21. **Перечислите базовые проверки для сообщений.**  
    Пользователь информируется сообщениями об успешном завершении операции; необратимые действия подтверждаются; введённые данные не сбрасываются после сообщения. GUI: правописание, соответствие смыслу, соответствие названий, унификация стилей, «крестик» при наличии «Отмены», фокус на «Нет» для удаления, соответствие цвета типу сообщения, невалидное значение не отображается в сообщении об ошибке, соблюдается согласование числительного и существительного.

## 4. Выводы

Checklist — краткий список проверок. Acceptance Sheet — перечень функций. Test Cases — подробные шаги и ожидаемый результат.
