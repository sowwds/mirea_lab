# Практическая работа № 6 — события и pytest fixtures

Дисциплина: «Технологии тестирования программных продуктов». Участники: Никитин Артемий, Ефремов Алексей, группа ЭФБО-10-23.

TemperatureSensor хранит температуру и уведомляет подписанные колбэки при её изменении. Тесты проверяют состояние, события, отписку и устойчивость к ошибкам обработчиков. Инструкция рассчитана на вашу **CachyOS Linux, x86_64**, с установленным **uv**.

## 1. Требования методички

Источник: [Практическая работа 6. События и fixtures](Практическая_работа_6_События_и_fixtures.pdf).

### Реализация

| Требование | Что сделано |
| --- | --- |
| Класс TemperatureSensor | Находится в `temperature_sensor.py`. |
| Методы subscribe, unsubscribe, set_temperature и свойство текущего значения | Реализованы `subscribe(callback)`, `unsubscribe(callback)`, `set_temperature(value)` и свойство `temperature`. |
| Уведомление только при фактическом изменении | Одинаковое значение приводит к выходу без вызова колбэков. |
| Безопасная отписка отсутствующего подписчика | Проверяется наличие колбэка; чужая и повторная отписки ничего не ломают. |

### Обязательные тесты

| Требование | Где проверяется |
| --- | --- |
| При смене значения один вызов с новым значением | `test_temperature_change`. |
| При том же значении вызова нет | `test_same_temperature`: целое 20 и дробное 20.0. |
| Несколько подписчиков получают одинаковое событие | `test_multiple_subscribers`: 2 и 3 подписчика. |
| После unsubscribe удалённый не вызывается, остальные вызываются | `test_unsubscribe`. |
| Начальное значение | `test_initial_temperature`: 0.0. |
| Параметризованная смена значений | `test_temperature_values`: 5 наборов. |
| Готовый сенсор предоставляется через fixture | Во всех соответствующих тестах используется `ready_sensor` из `conftest.py`. |

### Дополнения для полного балла

| Требование | Где проверяется |
| --- | --- |
| Негативный unsubscribe | `test_unsubscribe_unknown` и `test_repeated_unsubscribe`. |
| Ошибка одного подписчика не мешает остальным | `test_subscriber_exception`: ошибка первого, среднего или последнего колбэка. |

Дополнительно проверяются последовательность изменений с повторами и отсутствие дублирования при повторном subscribe. Всего **11 функций и 19 случаев**, все прошли. Методичка этой работы не задаёт минимальный процент покрытия и не требует установки pytest-cov.

## 2. Как устроен сенсор

Начальная температура по умолчанию — `0.0`. Это выбранное поведение: методичка требует тест начального значения, но не задаёт конкретное число. Конструктор также принимает `initial_temperature`.

1. `subscribe` запоминает колбэк; повторная подписка того же объекта не добавляет копию.
2. `set_temperature` сравнивает новое значение с текущим. Например, 20 и 20.0 равны и не создают повторного события.
3. При изменении сначала обновляется свойство `temperature`, затем вызывается `_notify`.
4. `_notify` проходит по снимку списка подписчиков и вызывает каждого с одним аргументом — новой температурой.
5. Обычное исключение `Exception` одного обработчика записывается через logging; цикл продолжается.
6. `unsubscribe` удаляет колбэк, если тот подписан. Повторная и чужая отписки безопасны.

Уведомления синхронные: происходят во время вызова `set_temperature`, отдельного потока или очереди нет. Модель не связана с физическим датчиком и не ограничивает диапазон температуры. Валидация специальных числовых значений и многопоточность в задании не определены.

## 4. Как работают fixtures и наблюдение за событиями

| Средство | Назначение в работе |
| --- | --- |
| `@pytest.fixture` | Отмечает функцию подготовки объекта для тестов. |
| `sensor` | Возвращает новый TemperatureSensor для проверки начальной температуры. |
| `ready_sensor(sensor)` | Получает sensor, устанавливает 20 и возвращает его для событийных проверок. Подписки добавляются уже в тесте. |
| Область жизни `function` | Значение по умолчанию: каждому случаю, в том числе строке параметризации, выделяется новый сенсор. |
| `Mock()` | Заменяет обработчик и записывает аргументы и число событий; выполняет роль наблюдателя, аналогичную QSignalSpy для данной модели. |
| `assert_called_once_with(value)` | Проверяет одно уведомление с конкретным значением. |
| `assert_not_called()` | Проверяет отсутствие лишнего события или вызова отписанного обработчика. |
| `call_args_list` и `call(...)` | Позволяют сравнить историю событий и её порядок. |
| `side_effect=error` | Моделирует исключение внутри обработчика. |
| `caplog` | Встроенная fixture pytest для перехвата logging; проверяет запись ошибки и исходное исключение. |

Подготовка не использует общих изменяемых объектов, реальных файлов или соединений. Очистка через yield не нужна: каждый тест получает новый сенсор, а внешних ресурсов нет. Импортировать `conftest.py` вручную не требуется — достаточно назвать нужную fixture в аргументах тестовой функции.

## 5. Подготовка на CachyOS Linux

Используется Python **3.14.8**, pytest **9.2.0** и установленный uv. Все команды выполняйте в каталоге этой работы:

```bash
cd "/home/aleksey/Documents/mirea_lab/7 sem/software_testing/pr6"
```

В текущем каталоге окружение уже создано. Проверка:



Активация окружения не требуется: используется явный путь `.venv/bin/python`. Команды подходят для Bash и Fish и не зависят от выбранной версии системного Python.

## 6. Как запустить и повторить результаты

### Все тесты

```bash
.venv/bin/python -m pytest test_temperature_sensor.py -v
```

Ожидаемый итог текущих исходников: **19 passed**. Это число случаев, а не функций: параметризация разворачивает некоторые из 11 функций в несколько проверок.

### Сохранение полного вывода

```bash
bash -o pipefail -c '.venv/bin/python -m pytest test_temperature_sensor.py -v --color=no | tee pytest_output.txt'
```

| Часть команды | Назначение |
| --- | --- |
| `.venv/bin/python -m pytest` | Запускает pytest из окружения Практики 6. |
| `test_temperature_sensor.py` | Выбирает файл с тестами сенсора. |
| `-v` | Показывает имена и результаты всех случаев. |
| `--color=no` | Убирает управляющие последовательности цвета из журнала. |
| `tee pytest_output.txt` | Показывает вывод и записывает его в файл, заменяя предыдущий журнал. |
| `bash -o pipefail -c` | Выполняет конвейер в Bash, сохраняя ошибочный статус при провале тестов, даже если tee успешно записал файл. Команду можно вызвать из Fish. |

Фрагмент ожидаемого вывода:

```text
collecting ... collected 19 items
test_temperature_sensor.py::test_initial_temperature PASSED
test_temperature_sensor.py::test_temperature_change PASSED
...
test_temperature_sensor.py::test_subscriber_exception[first] PASSED
test_temperature_sensor.py::test_subscriber_exception[middle] PASSED
test_temperature_sensor.py::test_subscriber_exception[last] PASSED
test_temperature_sensor.py::test_duplicate_subscription PASSED
19 passed
```

Время и абсолютный путь при повторном запуске могут отличаться. Проценты возле случаев — прогресс, не покрытие кода. Команда не измеряет coverage.

### Отдельные сценарии

Только негативные отписки:

```bash
.venv/bin/python -m pytest test_temperature_sensor.py::test_unsubscribe_unknown test_temperature_sensor.py::test_repeated_unsubscribe -v
```

Только ошибка первого подписчика:

```bash
.venv/bin/python -m pytest 'test_temperature_sensor.py::test_subscriber_exception[first]' -v
```

Список случаев без выполнения:

```bash
.venv/bin/python -m pytest test_temperature_sensor.py --collect-only -q
```

Показ подготовки и завершения fixtures:

```bash
.venv/bin/python -m pytest test_temperature_sensor.py::test_temperature_change -v --setup-show
```

В последней команде можно увидеть, как перед тестом готовятся `sensor` и зависимая от неё `ready_sensor`. Для итогового журнала запускайте весь набор, а не отдельный случай.

## 8. Частые проблемы

| Ситуация | Что проверить |
| --- | --- |
| `No module named pytest` | Установите зависимости через `uv pip install --python .venv/bin/python -r requirements.txt`. |
| `fixture ready_sensor not found` | Файл `conftest.py` должен лежать рядом с тестами; имена fixtures в аргументах функций должны совпадать с определениями. |
| `No module named temperature_sensor` | Перейдите в `pr6`, проверьте наличие `temperature_sensor.py` рядом с conftest и тестами. |
| Ошибка в числе уведомлений | Проверьте сравнение значений до уведомления, дубликаты подписок и использование нового сенсора для каждого случая. |
| Колбэк вызывается после отписки | Проверьте, что удаляется тот же объект обработчика, который был передан в subscribe. |
| RuntimeError выходит из теста ошибки подписчика | Обработку исключения нужно выполнять внутри цикла вокруг отдельного колбэка, чтобы продолжить уведомления. |
| caplog не содержит ожидаемой записи | Проверьте вызов `logger.exception`, имя логгера `temperature_sensor` и уровень ERROR. |
| В журнале ошибки обработчика, но тест прошёл | В сценарии с side_effect это ожидаемо: ошибка специально моделируется и проверяется, остальные колбэки должны выполниться. |
| Сам файл сенсора ничего не выводит | Запускайте pytest: файл сенсора определяет класс, но не содержит самостоятельного сценария. |
