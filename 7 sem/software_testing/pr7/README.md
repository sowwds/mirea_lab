## 5. Как устроена изоляция

`db_session` создаёт свою SQLite в памяти для каждого случая. StaticPool оставляет одно соединение, а check_same_thread=False разрешает работу с ним из потока TestClient. В отдельном приложении get_db переопределяется функцией, выдающей эту сессию; get_rates — функцией, возвращающей Mock курсов.

Заголовки admin и viewer получают токены реальным запросом к `/auth/login`, поэтому проверки доступа не обходят аутентификацию. make_item создаёт билеты через API. Название fixture оставлено как в методичке, хотя ресурс варианта — tickets.

После теста закрываются TestClient и сессия, освобождается engine, dependency_overrides очищается. Новое приложение также получает пустой словарь токенов. Общее состояние между случаями не сохраняется.

Фиктивные курсы: USD=0.01 и EUR=0.009 за 1 RUB. При цене 100 RUB ожидаются 1 USD и 0.9 EUR. Через side_effect можно задать RateUnavailable и проверить HTTP 502. Автоматическая fixture блокирует реальный HTTPTransport; тесты адаптера используют MockTransport.

## 6. Как повторить вводную ошибку

На исходном примере команда **должна завершиться неуспешно**: так подтверждается наличие ошибки в методичке.

```bash
bash -o pipefail -c 'WARMUP_APP=app_v0 .venv/bin/python -m pytest warmup/test_warmup.py -v --randomly-seed=20261112 --color=no | tee warmup_failure.txt'
```

Ожидается `1 failed`, причина — `assert 2 != 2`. Создание A и B, удаление A и создание C приводит к повторной выдаче ID 2 и потере B.

Исправленный вариант, используемый по умолчанию:

```bash
.venv/bin/python -m pytest warmup/test_warmup.py -v
```

Ожидается `1 passed`. NEXT_ID больше не зависит от числа оставшихся записей; fixture очищает словарь и восстанавливает счётчик для каждого запуска. Переменная WARMUP_APP в первой команде действует только внутри её Bash-процесса и не переключает последующие обычные прогоны.

## 7. Как повторить проверку чувствительности

Рабочий код уже восстановлен; журналы двух экспериментов приложены. Для самостоятельного повторения меняйте **одну строку за раз**, запускайте целевую группу, затем возвращайте исходную строку.

### Ошибка 1 — запись разрешена viewer

В `app/auth.py`, в require_admin, временно замените:

```python
if role != "admin":
```

на:

```python
if role not in ("admin", "viewer"):
```

Прогон:

```bash
bash -o pipefail -c '.venv/bin/python -m pytest tests/test_api.py::test_viewer_cannot_write -v --randomly-seed=20261112 --color=no | tee mutation_auth.txt'
```

Ожидаются **5 failed**: методы записи возвращают успех вместо 403. Верните `if role != "admin":` перед следующим экспериментом.

### Ошибка 2 — неверная конвертация

В конце converted_price в `app/main.py` временно замените:

```python
return {"currency": currency, "price": ticket.price * rate}
```

на:

```python
return {"currency": currency, "price": ticket.price / rate}
```

Прогон:

```bash
bash -o pipefail -c '.venv/bin/python -m pytest tests/test_api.py::test_price_uses_stubbed_rate -v --randomly-seed=20261112 --color=no | tee mutation_price.txt'
```

Ожидаются **2 failed**, поскольку расчёт цены отличается от ожидаемого. Верните умножение. Затем выполните полный прогон с покрытием из раздела 4: снова должны пройти все 86 случаев. Падающие журналы экспериментов сохраняются как доказательства, рабочие исходники остаются исправленными.

## 8. Самостоятельный запуск API

Этот режим нужен для ручных HTTP-запросов. Он использует локальную SQLite `tickets.db`, а не тестовую БД в памяти.

```bash
.venv/bin/python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8767
```

Команда проверена: GET /health вернул 200. В другом терминале:

```bash
curl --max-time 10 http://127.0.0.1:8767/health
curl --max-time 10 -X POST http://127.0.0.1:8767/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin123"}'
```

Ответ входа содержит access_token. Подставьте его вместо `ВАШ_ТОКЕН`:

```bash
curl --max-time 10 -X POST http://127.0.0.1:8767/tickets -H 'Content-Type: application/json' -H 'Authorization: Bearer ВАШ_ТОКЕН' -d '{"name":"Концерт","price":1000,"seats":100}'
curl --max-time 10 http://127.0.0.1:8767/tickets -H 'Authorization: Bearer ВАШ_ТОКЕН'
```

Интерактивная документация доступна по адресу `http://127.0.0.1:8767/docs`. Через Authorize можно вставить токен и выполнять маршруты. Остановка сервера — Ctrl+C.

| Роль | Имя | Пароль | Права |
| --- | --- | --- | --- |
| admin | admin | admin123 | Чтение и запись. |
| viewer | viewer | viewer123 | Только чтение, включая конвертацию цены. |

Реквизиты учебные, токены случайные и хранятся только в памяти процесса; после перезапуска входите заново. Срок действия и JWT в этой реализации не используются.

В самостоятельном режиме запрос `/tickets/{id}/price?currency=USD` обращается к реальному внешнему сервису, поэтому требует сети и при недоступности возвращает 502. Курсы тестов не применяются. Базовая цена — RUB, итог — цена × число единиц USD/EUR за 1 RUB. Источник: [Rates By Exchange Rate API](https://www.exchangerate-api.com), [описание открытого endpoint](https://www.exchangerate-api.com/docs/free). Адаптер выполняет запрос при каждом обращении; для учебного ручного прогона делайте единичные запросы, учитывая ограничения провайдера.

## 9. Частые проблемы и файлы для сдачи

| Ситуация | Что проверить |
| --- | --- |
| Не найдены fastapi, sqlalchemy или pytest | Установите requirements-lock.txt в `.venv`, запускайте тот же `.venv/bin/python`. |
| `No module named app` | Перейдите в `pr7`; используйте `python -m pytest`, как в инструкции. |
| Нет таблицы tickets в тестах | Проверьте create_all, StaticPool, check_same_thread=False и подмену get_db в conftest. |
| Проверки зависят от порядка | Не используйте tickets.db в тестах; каждому случаю нужны новые engine, сессия, приложение и токены. |
| Все ручные запросы дают 401 | Получите токен после текущего запуска сервера и передайте `Authorization: Bearer ...`. |
| 403 при записи | Убедитесь, что используется токен admin, а не viewer. |
| 409 при изменении мест | Новый seats должен остаться в диапазоне 0–300. |
| 422 при POST или PATCH | Проверьте типы, обязательные поля, имя, цену, диапазон мест; PATCH не принимает пустой объект или null. |
